# Архитектура

Модульный монолит: один репозиторий Next.js + отдельный Node.js-процесс worker, общая PostgreSQL.
Микросервисов, очередей и кэшей нет — для объёма одного города они не нужны.

```
                ┌──────────────────────────┐        ┌──────────────────────────┐
  браузер ────▶ │ Next.js (src/app)        │        │ worker (src/worker)      │
                │  страницы, Server Actions│        │  расписание + очередь    │
                └────────────┬─────────────┘        └────────────┬─────────────┘
                             │  чтение, постановка в очередь      │  сбор, оценка
                             ▼                                    ▼
                ┌──────────────────────────────────────────────────────────────┐
                │ src/server/services — бизнес-сценарии (use cases)            │
                │ src/server/sources  — источники данных (ListingSource)       │
                └────────────┬───────────────────────────────┬─────────────────┘
                             ▼                               ▼
                ┌──────────────────────────┐   ┌──────────────────────────────┐
                │ src/domain — чистая      │   │ PostgreSQL (Prisma 7 +       │
                │ логика: деньги, оценка,  │   │ @prisma/adapter-pg)          │
                │ Deal Score, нормализация │   └──────────────────────────────┘
                └──────────────────────────┘
```

## Слои

| Папка | Ответственность | Зависит от |
| --- | --- | --- |
| `src/domain/` | Бизнес-правила без БД и HTTP: денежная арифметика (`money.ts`), проверка и нормализация объявлений, поиск аналогов, оценка, уверенность, Deal Score, объяснения | ничего (кроме zod) |
| `src/server/sources/` | Источники объявлений за интерфейсом `ListingSource`: синтетика, файл, заготовка Krisha API | domain |
| `src/server/services/` | Сценарии: конвейер обновления, сохранение, дубликаты, пересчёт оценок, очередь, запросы для страниц | domain, sources, lib |
| `src/server/auth/` | Сессия администратора (HMAC-cookie), ограничение попыток входа | config |
| `src/app/` | Страницы и Server Actions — только отображение и вызов сервисов | services, components |
| `src/components/` | UI-компоненты (shadcn/ui в `components/ui`) | domain (форматирование, подписи) |
| `src/worker/` | Точки входа фонового процесса и CLI | services |
| `src/config/env.ts` | Единственное место чтения `process.env`, проверка через zod | — |
| `src/lib/` | Prisma-клиент, advisory lock, утилиты (retry, timeout, concurrency, logger), zod-схемы URL | config |

## Поток данных обновления

`runCollection()` в `src/server/services/collectionService.ts`:

1. Берёт advisory lock PostgreSQL (`pg_try_advisory_lock` на отдельном соединении) — одновременно идёт только
   один цикл; при падении процесса блокировка снимается автоматически.
2. Получает сырые записи от источника — с тайм-аутом и повторами (экспоненциальная задержка; постоянные ошибки
   вроде «источник не подключён» не повторяются).
3. Проверяет каждую запись (`rawListingSchema`), нормализует, считает отпечаток квартиры и хеш содержимого.
4. Сохраняет идемпотентно: ключ `(sourceId, externalId)`. Без изменений — только `lastSeenAt`; при смене цены —
   запись в `ListingPriceHistory`.
5. Для источников с полным срезом деактивирует исчезнувшие объявления (пустой ответ — ошибка, а не «всё снято»).
6. Пересчитывает дубликаты и оценки всех активных объявлений.
7. Пишет итог в `CollectionRun` (счётчики, первые 50 ошибок проверки) и статус в `DataSource`.

Админка не выполняет сбор в HTTP-запросе: она ставит `CollectionRun` со статусом `QUEUED`, worker забирает его.

## Ключевые решения

- **Деньги — целые тенге (`BigInt`), площадь — сотые доли м² (`bigint` в домене, `Decimal` в БД).**
  Формулы скидки и разницы точные; float используется только для весов похожести.
- **Синтетика и реальные данные не смешиваются**: аналоги ищутся только в том же наборе, а страницы показывают
  реальные данные, как только они появятся (`dataRealmService`).
- **Одна текущая оценка на объявление** (`Valuation.listingId` уникален) — пересчитывается целиком; история
  оценок не нужна, история цен хранится отдельно.
- **Next.js 16 + Cache Components**: все чтения БД выполняются на запрос (`await connection()` внутри
  `<Suspense>`), кэш `use cache` не используется — данные должны быть свежими.
