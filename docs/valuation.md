# Алгоритм оценки (кратко)

Полное описание с актуальными числами — на странице «Как считаем» (`/methodology`), она строится из тех же
констант, что и расчёт. Код: `src/domain/valuation/` и `src/domain/deals/dealScore.ts`.

1. **Аналоги** (`comparables.ts`): тот же набор данных, район, комнатность (5+ — одна группа), площадь ±30%,
   видели не позже 180 дней, не дубликат, правдоподобная цена за м².
2. **Уровни близости**: ЖК → микрорайон + похожий дом → район + похожий дом → район + та же эпоха застройки.
   Сначала все уровни с тем же классом ремонта, затем — смешанный ремонт (с предупреждением `CONDITION_MISMATCH`).
   Берётся первый уровень, где после удаления выбросов ≥ 5 аналогов, иначе `INSUFFICIENT_DATA`.
3. **Выбросы** (`statistics.ts`): IQR × 1,5 и полоса ±45% от медианы.
4. **Цена за м²** — взвешенная медиана (вес = похожесть), диапазон — 25–75 перцентили.
5. **Формулы** (`money.ts`): `marketValue = ppsm × area`, `discount = (market − price) / market × 100`,
   `difference = market − price`.
6. **Уверенность** (`confidence.ts`): количество (30%), согласованность цен (30%), уровень близости (25%),
   похожесть (15%).
7. **Deal Score** (`dealScore.ts`): скидка 55%, уверенность 25%, свежесть 10%, полнота 10%, минус штрафы за риски.

Версия метода хранится в `Valuation.method`. После изменения алгоритма выполните `npm run revalue`.

## Известные ограничения

- Только цены предложения; реальные цены сделок недоступны.
- Нет гедонических поправок (например, «+7% за свежий ремонт»): вместо них — отбор аналогов с тем же классом
  ремонта. Поправки можно добавить, когда накопятся реальные данные для их оценки.
- Ликвидность не учитывается — нет обоснованных данных о сроках продажи.
