# Источники данных

| Ключ | Класс | Статус | Полный срез* |
| --- | --- | --- | --- |
| `synthetic` | `SyntheticSource` | Работает. Вымышленные объявления, помечены как тестовые | да |
| `file-import` | `FileImportSource` | Работает. CSV/JSON через CLI или раздел «Управление» | нет |
| `krisha-api` | `KrishaApiSource` | **Не подключён** — нет разрешения и API | да |

\* Полный срез: каждый запуск возвращает все активные объявления, поэтому отсутствующие считаются снятыми.

## Почему нет сбора с Krisha.kz

Пользовательское соглашение Krisha.kz (krisha.kz/content/special/agreement, проверено 10.10.2026):

- п. 5.3 — запрещено использовать автоматические программы для доступа к сайту и извлекать материалы других
  пользователей вручную или автоматически без письменного разрешения АО «Колёса»;
- п. 5.5.6 — запрещено копировать, воспроизводить и распространять информацию с сайта без разрешения;
- п. 8.1 — запрещено извлекать сведения способами, не предусмотренными соглашением.

Официального публичного API не найдено. Решение и альтернативы — в [ADR 0001](adr/0001-krisha-data-access.md).

## Формат импорта

Файл CSV (разделитель `,` или `;`, UTF-8) или JSON (массив объектов или `{ "listings": [...] }`).
Примеры: [`data/examples/listings.example.csv`](../data/examples/listings.example.csv),
[`data/examples/listings.example.json`](../data/examples/listings.example.json).

| Поле | Обязательное | Формат |
| --- | --- | --- |
| `externalId` | да | строка до 100 символов, уникальна в пределах источника |
| `priceKzt` | да | целое число тенге (пробелы допускаются: `"42 000 000"`) |
| `totalArea` | да | м², 10–1000, запятая или точка |
| `rooms` | да | 1–20 |
| `district` | да | русское название района («Бостандыкский», «Бостандыкский р-н») или код (`BOSTANDYK`) |
| `url` | нет | только `http(s)://` |
| `city`, `dealType`, `propertyType` | нет | если указаны: Алматы / продажа / квартира — иначе запись отклоняется |
| `publishedAt`, `updatedAt` | нет | дата ISO (`2026-09-28`) |
| `livingArea`, `kitchenArea`, `ceilingHeight` | нет | числа |
| `microdistrict`, `address`, `complexName` | нет | строки |
| `buildingType` | нет | панельный / кирпичный / монолитный / иной |
| `yearBuilt`, `floor`, `floorsTotal` | нет | целые |
| `condition` | нет | черновая отделка / требует ремонта / среднее / хорошее / свежий ремонт |
| `sellerType` | нет | собственник / агент / застройщик |
| `furnished` | нет | да / нет |
| `description` | нет | до 5000 символов; храните, только если у вас есть права на текст |

Пустые значения сохраняются как `null` — недостающие характеристики не выдумываются.

Не хранятся (пока нет источника, который их достоверно отдаёт):
- **отдельный «тип ремонта»** — объединён с `condition`, как в формулировках объявлений Krisha.kz
  («свежий ремонт», «черновая отделка» и т. д.);
- **показатели ликвидности** (просмотры, срок экспозиции) — поэтому Deal Score их не учитывает;
- **фотографии и контакты продавцов** — без подтверждённых прав на хранение.
Ограничения: `IMPORT_MAX_FILE_MB` (5 МБ), `IMPORT_MAX_ROWS` (20 000 строк). Некорректные строки пропускаются,
ошибки видны в журнале запусков.

## Как подключить разрешённый API

1. Реализуйте `fetchListings()` и `checkStatus()` в `src/server/sources/krishaApiSource.ts` по документации API.
   Верните записи в формате таблицы выше — проверка и нормализация уже сделаны конвейером.
2. Ключи API — только в переменных окружения, добавьте их в `src/config/env.ts` и `.env.example`.
3. Соблюдайте лимиты API: повторы и тайм-ауты уже есть в `collectionService`, параллелизм запросов к API
   ограничьте в самом адаптере.
4. Добавьте ключ в `SCHEDULED_SOURCES` (например, `krisha-api`). Как только появятся реальные объявления,
   интерфейс автоматически переключится на них и уберёт баннер демонстрационного режима.
