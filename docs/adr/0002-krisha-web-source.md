# ADR 0002. Сбор со страниц выдачи Krisha.kz

- Статус: принято (частично заменяет ADR 0001)
- Дата: 2026-10-11

## Контекст

ADR 0001 отклонил парсинг сайта: пользовательское соглашение Krisha.kz (п. 5.3, 5.5.6, 8.1) запрещает
автоматизированный доступ без письменного разрешения АО «Колёса». Разрешения по-прежнему нет, официального API тоже.
Владелец проекта решил добавить сбор со страниц сайта и принимает связанный с этим правовой риск
(нарушение соглашения, возможная блокировка).

## Решение

Источник `krisha-web` (`src/server/sources/krishaWebSource.ts`, разбор — `krisha/parseSearchPage.ts`):

- **выключен по умолчанию** — `KRISHA_WEB_ENABLED=true` включает его осознанно;
- только страницы, не закрытые robots.txt: выдача `/prodazha/kvartiry/almaty/?page=N` без фильтров;
  `/ajax/`, `/captcha`, фильтры (`raion=` и т. п.) и детальные страницы не запрашиваются;
- по одной странице, пауза `KRISHA_WEB_DELAY_MS` (≥ 2 с), не больше `KRISHA_WEB_MAX_PAGES` (≤ 20) за запуск,
  честный `User-Agent`;
- **блокировки не обходятся**: капча, 403 или 429 → `SourceBlockedError`, запуск останавливается без повторов;
  ротации IP, подмены браузера и решения капчи нет и не будет;
- не сохраняются фотографии, контакты, имена продавцов и текст описания — только характеристики квартиры и ссылка.

`KrishaApiSource` остаётся заготовкой под официальный доступ.

## Последствия

- Берутся только свежие объявления с первых страниц (`providesFullSnapshot = false`): снятые с публикации
  не деактивируются автоматически.
- Вёрстка сайта может измениться — тогда карточки перестанут распознаваться (пустая выдача или массовые
  отклонения в журнале запуска). Тест `tests/unit/krishaWeb.test.ts` закрепляет текущую вёрстку.
- Если АО «Колёса» потребует прекратить сбор или даст API — источник выключается/заменяется адаптером API.
