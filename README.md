# Almaty Deal Finder

Бесплатный аналитический сервис для поиска потенциально недооценённых квартир в Алматы. Для каждой квартиры
он оценивает рыночную стоимость по похожим объявлениям, считает скидку к рынку, Deal Score, уверенность
оценки и риски — и объясняет, откуда взялись цифры.

> **Статус источника данных.** Источник `krisha-web` читает первые страницы выдачи Krisha.kz (по умолчанию
> выключен, `KRISHA_WEB_ENABLED`). Пользовательское соглашение Krisha.kz запрещает автоматизированный сбор без
> письменного разрешения АО «Колёса», публичного API нет — включая источник, вы принимаете этот риск на себя
> ([ADR 0002](docs/adr/0002-krisha-web-source.md)). Ещё работают импорт CSV/JSON (для данных, на которые у вас
> есть права) и синтетические тестовые данные, всегда помеченные в интерфейсе.
> Подробнее — [docs/data-sources.md](docs/data-sources.md).

### Нагрузка на Krisha.kz

Один запуск `krisha-web` — до `KRISHA_WEB_MAX_PAGES` страниц выдачи (по умолчанию 5, максимум 20) строго по одной,
с паузой `KRISHA_WEB_DELAY_MS` (по умолчанию 4 с, минимум 2 с). Worker запускает источник не чаще раза в
`WORKER_INTERVAL_MINUTES` (по умолчанию 60 мин): при 20 страницах это до 20 запросов в час, ~480 в сутки.
Ручные запуски из «Управления» — не чаще раза в `MANUAL_RUN_COOLDOWN_MINUTES`. Капча, 403/429 или защита SafeLine
(HTTP 468) останавливают запуск без повторов. Объявления, не встречавшиеся в выдаче 14 дней, помечаются
«Давно не обновлялось на сайте» и не участвуют в оценке.

## Пользователи и доступ

Все аккаунты хранятся в таблице `User`. Если задан `SITE_PASSWORD`, сайт видят только зарегистрированные:

1. Человек открывает `/register` и вводит имя, логин и общий пароль. С неверным паролем аккаунт не создаётся,
   с верным — создаётся и сразу входит на сайт (одобрение администратором выключено).
2. Дальше он входит на `/login` логином и общим паролем (сессия — 30 дней).
3. Администратор в «Управление» → «Пользователи» может заблокировать или удалить аккаунт.

**Администратор** — аккаунт с ролью `ADMIN` и личным паролем (в базе только хеш scrypt). Общий пароль к нему не
подходит. Создать администратора или сменить ему пароль (пароль спрашивается скрыто, от 12 символов):

```bash
npm run admin:create -- <логин> "<Имя>"
```

Администратор входит на `/login`, в шапке появляется «Управление» (сессия — 12 часов). Вкладки: пользователи и
обновления данных (с предупреждением, если данные перестали обновляться); «Журнал действий» — кто из
администраторов что и когда сделал; «База данных» — все таблицы, просмотр по страницам и удаление строк.
Выход завершает сессии аккаунта на всех устройствах. После 10 неверных паролей за 15 минут адрес блокируется.
Обычному пользователю `/admin` отвечает «не найдено». Блокировка действует не позже чем через 30 секунд.
Пароль пользователей общий, поэтому зная его, можно войти под любым обычным логином — это защита
«от посторонних». Без `SITE_PASSWORD` сайт открыт всем, но «Управление» — по-прежнему только администратору.

## Стек

Next.js 16 (App Router, React 19), TypeScript, Tailwind CSS 4 + shadcn/ui, PostgreSQL 17, Prisma 7 (`@prisma/adapter-pg`),
zod, Vitest, Playwright. Фоновый worker — отдельный Node.js-процесс (`tsx`).

## Быстрый старт

Нужны Node.js 22+, Docker Desktop (для локальной БД и тестов).

```bash
npm install                 # зависимости + генерация Prisma Client
cp .env.example .env        # затем заполните SESSION_SECRET (команда генерации — в файле)
npm run db:up               # PostgreSQL 17 в Docker на localhost:5434 (+ тестовая база)
npm run db:migrate          # применить миграции
npm run seed                # загрузить синтетические тестовые данные
# или настоящие: KRISHA_WEB_ENABLED=true в .env, затем npm run collect -- krisha-web
npm run dev                 # сайт на http://localhost:3100
npm run worker              # в отдельном терминале: фоновые обновления 24/7
```

На Windows вместо постоянного `npm run worker` можно поставить задачу в Планировщик —
`scripts/worker-once.cmd` каждые 15 минут, лог в `logs/worker.log` (команда — в [docs/deployment.md](docs/deployment.md)).

## База данных: локально или Supabase

Адрес — `DATABASE_URL` в `.env`, схема — параметр `?schema=` в нём же.

- **Локально (по умолчанию):** PostgreSQL в Docker, `localhost:5434`, схема `public`.
- **Supabase:** в `DATABASE_URL` — **Session pooler** (порт 5432): через него работают worker и миграции,
  блокировке «одно обновление за раз» нужно постоянное соединение. Сайт на Vercel сам переключается на
  **Transaction pooler** (6543): у Session pooler всего 15 соединений на проект, а бессерверные функции
  открывают их много. Таблицы — в своей схеме `deal_finder`: так они не смешиваются с другими приложениями
  проекта и не попадают в публичный Data API Supabase. Соединение проверяется корневым сертификатом Supabase
  из `certs/`. Пример строки — в `.env.example`; после смены адреса выполните `npm run db:migrate`.

Тесты (integration, E2E) всегда работают с локальной `DATABASE_URL_TEST` и очищают её — рабочую базу не трогают.

## Переменные окружения

Полный шаблон с пояснениями — `.env.example`. Читаются и проверяются только в `src/config/env.ts`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | — | Рабочая БД (обязательна) |
| `DATABASE_URL_TEST` | — | БД для integration/E2E-тестов |
| `DATABASE_POOL_MODE` | Vercel: `transaction`, иначе `session` | Режим Supabase pooler (порт 6543 или 5432) |
| `DATABASE_POOL_MAX` | Vercel: `2`, иначе `5` | Соединений с БД на процесс (у Supabase Session pooler всего 15 на проект) |
| `SESSION_SECRET` | — | Подпись cookie сессий (≥ 32 символов); без него вход выключен |
| `SITE_PASSWORD` | — | Общий пароль пользователей (≥ 8 символов); без него сайт открыт всем |
| `SCHEDULED_SOURCES` | `synthetic` | Источники для worker'а через запятую, например `krisha-web` |
| `WORKER_INTERVAL_MINUTES` | `60` | Как часто worker обновляет каждый источник |
| `MANUAL_RUN_COOLDOWN_MINUTES` | `5` | Минимальный интервал между ручными запусками |
| `KRISHA_WEB_ENABLED` | `false` | Включить сбор со страниц Krisha.kz |
| `KRISHA_WEB_MAX_PAGES` | `5` | Страниц выдачи за запуск (1–20) |
| `KRISHA_WEB_DELAY_MS` | `4000` | Пауза между страницами (≥ 2000) |
| `IMPORT_MAX_FILE_MB`, `IMPORT_MAX_ROWS` | `5`, `20000` | Ограничения импорта CSV/JSON |

Синтетические и реальные данные не смешиваются: как только в БД есть реальные объявления, сайт показывает только их.
Поэтому для рабочей базы с Krisha.kz `synthetic` в `SCHEDULED_SOURCES` не нужен.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` / `build` / `start` | Сайт (порт 3100) |
| `npm run worker` | Постоянный фоновый процесс: плановые обновления + ручные запуски из очереди |
| `npm run worker:once` | Один цикл worker'а — для cron / Планировщика заданий |
| `npm run collect -- <источник>` | Обновить один источник: `synthetic`, `krisha-web` |
| `npm run import -- путь/к/файлу.csv` | Импортировать CSV/JSON |
| `npm run revalue` | Пересчитать оценки без загрузки данных |
| `npm run seed` | То же, что `collect -- synthetic` |
| `npm run admin:create -- <логин> "<Имя>"` | Создать администратора или сменить ему пароль (завершает его сессии) |
| `npm run backup` | Резервная копия схемы БД в `backups/` (нужен Docker), см. docs/deployment.md |
| `npm run prune` | Удалить устаревшие данные сейчас (worker делает это сам раз в сутки), см. docs/deployment.md |
| `npm run typecheck` / `lint` | Проверка типов / линтер |
| `npm test` | Unit-тесты |
| `npm run test:integration` | Интеграционные тесты (тестовая БД `deal_finder_test`) |
| `npm run test:e2e` | E2E Playwright (собирает приложение, порт 3101, тестовая БД, установленный Chrome) |
| `npm run db:migrate:dev -- --name <имя>` | Создать миграцию после изменения `prisma/schema.prisma` |

Один тест: `npx vitest run tests/unit/money.test.ts -t "10,64%"`, один E2E: `npx playwright test -g "фильтр"`.
